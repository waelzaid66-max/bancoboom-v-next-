# VNX-02 — Messenger Idempotent Send Foundation

## Decision

The recoverable Git corpus did not contain the claimed advanced Codex Messenger
implementation. The vNext base contained optimistic retry behavior but no stable
client attempt identifier in the database or API. This batch therefore performs
a bounded reconstruction; it is not presented as a recovered historical patch.

## Implemented invariant

One logical client send owns one UUID. The mobile client reuses that UUID on an
ambiguous retry. The database elects exactly one durable message for the tuple
`(conversation_id, sender_id, client_message_id)`. Only the winning insert may
advance the conversation preview/unread projection or create a notification.

The request field remains optional for older clients. New and legacy rows can
therefore coexist, while the current mobile thread always supplies the UUID.

## Preserved security and product invariants

- Conversation participant authorization happens before replay lookup.
- Idempotency is scoped by conversation and authenticated sender; one sender
  cannot retrieve another sender's attempt by guessing its UUID.
- Reply targets remain constrained to the same conversation.
- Shared listings retain active/public visibility validation for first attempts.
- First-party attachment ownership, media policy validation, and private upload
  finalization still happen before a new message becomes durable.
- Legacy clients remain accepted; this migration does not rewrite old rows.
- No changes were made to `SectionSearchApp.tsx`, Maps, headers, storage ACLs,
  payments, CI, Docker, or Coolify in this batch.

## Explicitly unproven

The new PostgreSQL integration test could not run because this workspace has no
`DATABASE_URL`, `psql`, Docker, or PostgreSQL service. The DB race and transaction
behavior is therefore **UNPROVEN at runtime** until CI/staging runs the test.

Notification creation remains after the message/unread database transaction.
Retries cannot duplicate it, but a process crash between the transaction commit
and notification creation can still lose the notification. A transactional
outbox is intentionally deferred to a separate reviewed batch.

Native offline/reconnect behavior, push delivery, email delivery, live private
media, Android, iOS, and physical-device journeys are also unproven.
